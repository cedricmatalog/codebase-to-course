Trace a course being built

Manifest, ledger, builder, page

The primary path is assembly: the agent writes evidence and module fragments, and a trusted builder decides whether they may become a page.

Do this next: advance the trace to watch a course move from evidence to a finished page.

  1. The agent records claims and evidence while reading the repository.
  2. Module fragments are written, each claim anchored to its ledger entry.
  3. The builder validates the manifest, the ledger, and every fragment.
  4. Only then is index.html assembled and replaced atomically.

The builder is a gate, not a template engine

Module fragments may not contain document-level or executable markup at all.

    const forbiddenTag = source.match(/<\/?\s*(html|head|body|style|script|iframe|object|embed|base|meta|link|img|audio|video|source|track|form)\b/i);

One broken exercise cannot take the page down

The shared runtime wraps every exercise initialiser, so a malformed walkthrough degrades to static content instead of disabling navigation and everything after it.

CODE
  function initAll(selector, initialize) {
    $$(selector).forEach((element, index) => {
      try {
        initialize(element, index);
      } catch (_) { /* This exercise stays static; navigation and later patterns keep working. */ }
    });
  }
