What this repository is

A skill that writes onboarding courses

This repository is not an application. It is an — a package of instructions that an AI coding agent reads when someone asks it to onboard an engineer to an unfamiliar codebase. The agent reads the repository under analysis and writes a self-contained browser course about it.

Every generated course starts from the same six-module arc, moving from what the system does to how to change it.

CODE
1. What this system does, who uses it, the vocabulary you will hear, the full repository map, and how its parts depend on each other
2. How to get it running, and how you know a change took effect: configuration, environment, the edit-to-result loop, and where output appears
3. The primary path end to end, its failures, and side effects
4. Testing and debugging evidence
5. Delivery, release, or deployment boundaries, when repository evidence exists
6. How this team expects changes to be made, and a first low-risk change with its validation steps and the signal that proves it worked
PLAIN ENGLISH

Start with what it does and who uses it, not the architecture.

Then getting it running, and knowing a change took effect.

Then the real path through the code, end to end.

Then how you know it works, and how it ships.

Then the first change you will actually make.

The promise that shapes everything

The product is not prose about code — it is prose with a traceable status attached to every claim.

CODE
- `verified`: directly supported by cited source at the recorded revision
- `inferred`: a bounded interpretation consistent with evidence but not explicitly stated
- `unverified`: a documented or discovered operational claim that was not safely tested
- `undocumented`: required information is absent from inspected evidence
PLAIN ENGLISH

Backed by cited source at a recorded revision.

A bounded reading the evidence allows but does not state.

Documented but never actually run or tested.

The repository simply does not say.

Why it matters

Fluent, confident, wrong is the standard failure of AI-written documentation. A status on every sentence is how this repository refuses to make that trade.

The course is a snapshot rather than living documentation: the source suggests a regenerate-and-check model, since the only documented refresh path is an explicit staleness check followed by a rebuild.
